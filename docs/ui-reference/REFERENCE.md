## 1. How to run the reference app
- Launch (normal): `streamlit run server_app.py` (server_app.py is a `st.App` wrapping app.py + Starlette routes `/auth/session`, `/auth/logout` and a cookie-cleanup middleware). Docker/Render: `scripts/entrypoint.sh` -> `streamlit run server_app.py --server.headless true --server.address 0.0.0.0 --server.port $PORT`.
- Used here: `CERVECERIA_DB_PATH=<scratch>/ref.db .venv/bin/streamlit run server_app.py --server.headless true --server.port 8502` (env var confirmed in database/connection.py). Streamlit 1.57.0, Python 3.14, venv at `chusetts/.venv`.
- DB: a COPY of data/gestion_cerveceria.db (real DB only had users admin/user). Test users were added to the copy via `scripts/create_user.create_user`: **testadmin / testadmin (admin)** and **testcajero / testcajero (cajero)** (usernames are lowercase; seeds.py only seeds them on an empty users table). Product names/prices in the copy were edited for nicer screenshots; stray open turnos were deleted. The repo and the real DB were not modified (git status clean).
- No `.streamlit/config.toml` exists: Streamlit default theme (light, font "Source Sans", primary #ff4b4b) + all branding through injected CSS. `page_title='Chusetts Gestión'`, `page_icon='🍺'`, `layout='wide'`, `initial_sidebar_state='expanded'`.
- Headless browser: `/usr/bin/google-chrome` 155 + `playwright-core` (installed in `<base>/../pw`). Streamlit process on 8502 was killed (port verified free).
- Dark mode: theme.css has `@media (prefers-color-scheme: dark)` overrides (tokens below). Light is the default; 2 dark shots captured.

## 4. Navigation structure
URL = path (st.Page url_path). Default page of each role lives at `/` (other url_path ignored for default; `/inicio` and `/caja` actually return a "Page not found" dialog).
- Not logged in: only `Ingresar` (/login, default). Page title 'Chusetts Gestión', favicon 🍺.
- admin: Inicio (/, default), Carga rápida (/carga-rapida; registered but HIDDEN from sidebar; reached from nothing except dialogs/go_to), Productos (/productos), Movimientos (/movimientos), Mi turno (/mi-turno), Cajas (/cierre-de-caja), Reportes (/reportes), Administración (/administracion). Sidebar order: Inicio, Productos, Movimientos, Mi turno, Cajas, Reportes, Administración.
- cajero: Caja (/, default), Nueva venta (/nueva-venta), Mis tickets (/mis-tickets), Mi turno (/mi-turno).
- Sidebar: title `🍺 Chusetts`; caption `Usuario: {display_name}`; caption `Rol: {role}`; label `Menú`; nav buttons (`● Title` active / `○ Title`); divider; cajero only note `Modo caja: solo ventas y anulaciones propias.`; button `Cerrar sesión`.
- Permissions: `ensure_permission` shows st.error `No tenés permisos para acceder a esta función.` and stops (cajero hitting admin URLs; page not in navigation anyway).
- Auth/session: login -> create_session + single-use handoff code -> JS redirect to `/auth/session?code=..` which sets httpOnly cookie (30 days, DB expiry authority, sliding 12h renewal) and 303s to `/`. Logout: revoke server-side then `/auth/logout` (delete cookie, 303 `/login`). Cookie restore happens on page load.

## 7. Interaction patterns (summary)
- Every click = full script rerun (Streamlit); the user perceives a short flash/dim of stale content (~0.3-1 s). Navigation is real URL change via sidebar buttons (st.switch_page); there is no browser back/forward state for sub-views (product detail, master-data ficha live in session state).
- Dialogs (st.dialog): `Cargar gasto`, `Cargar compra` (title `Cargar movimiento`), `Cargar producto`/`＋ Nuevo producto` (title `Nuevo producto`). Dismiss with X/Escape/click outside. Saving in the quick-entry dialog: success + clear + rerun (dialog closes since the dialog function is not re-invoked after the rerun). Product create closes dialog and opens product detail page.
- Confirmations: no modal confirms. Destructive actions use a confirm checkbox that enables the button (desactivar producto, revocar sesión, cerrar aplicación) or mandatory reason text (anular ticket/movimiento, reabrir caja, ajustes).
- Feedback: success/error alerts inline (above the control or at page top as "flash" after rerun); toasts only for (a) admin "Cerrar caja" with no open cash (icon 🪙) and (b) product flash (icon ✅, plus alert). Flash messages survive exactly one rerun.
- Keyboard: standard Streamlit: Enter in a text input commits its value (reruns) but does not press buttons; inside st.form, Enter in a single-line text input submits the form (used by Ingresar? NO, login isn't a form). Selectbox is searchable by typing. Number inputs accept typing, arrows hidden.
- Redirects: after login -> `/`; logout -> `/login`; `Abrir mi caja`, `Ir a Mi turno` -> /mi-turno; `Abrir nueva venta` -> /nueva-venta; `Ver mis tickets` -> /mis-tickets; admin `Cerrar caja` -> /cierre-de-caja.
- Roles: cajero can only open/close own turno, sell, view/annul own tickets. Admin has everything else; admin can open his own turno too.

## 8. Known defects / quirks of the reference (do NOT copy blindly; decide with product owner)
1. Mobile: sidebar open by default squeezes content (see above). Login hero text clipped at 390px.
2. Admin Inicio can crash with DuplicateElementKey (record_list key) when Hoy and Mes lists start with the same record.
3. Qty -/+ buttons and number steppers are hidden (intentional CSS) so cart quantity can only grow by tapping `Agregar` again or be removed with `Quitar`.
4. `/inicio` and `/caja` url_paths are overridden by default page `/` (give "Page not found" dialog).
5. Disabled buttons keep orange look. All secondary buttons are visually primary.
6. `Carga rápida` is not in the sidebar (reachable only via dialog logic); `Ajuste Stock` option in it renders the Venta form.
7. Server shutdown button in Administración -> Sistema calls os._exit(0).
8. Dates/timestamps are shown as raw ISO strings in several record_lists; percentages use dot decimals but number inputs show comma decimals (es locale from browser).
